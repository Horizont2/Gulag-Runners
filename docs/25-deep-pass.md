# Глибокий розбір: що виміряно і що робити далі

Зроблено за станом коду і сцен, не на пам'ять. Кожен пункт — з числом під ним.

## Розмір

```
Sim           6 245 рядків   детермінований, без float, без Unity
Presentation  9 993
Editor        3 995          тули, які не компілюються в білд
Menu            790
Audio           798
Input           502
```

Симуляція вдвічі менша за презентацію — правильна пропорція для гри, де симуляція
мусить бути ідентичною на двох пристроях.

## 1. Найбільша прогалина: гравець не бачить половини своїх ресурсів

Пошук по всій презентації: **жоден файл не читає `StaminaCharges`.** Нуль.

Тобто заряди витрачаються на тримання блоку (один за 0.8 с) і на важкий удар по блоку
(два), блок ламається і лишає бійця беззахисним на 0.7 с — і **нічого з цього не видно**.
Гравець не може ні планувати блок, ні зрозуміти, чому його раптом зламали.

Це прямо б'є по тому, що щойно виправлено: блок став справжньою відповіддю на спам, але
відповіддю, якою неможливо свідомо керувати.

Здоров'я видно (`FighterDamageView`: рани на тілі, знебарвлення). Фазу матчу видно (двері
клітки, сирена, світло інтро). Заряди — ні.

## 2. У грі немає жодного UI

```
Arena_Demo    231 обʼєкт,  86 префабів,  0 Canvas
SetupScene     40 обʼєктів, 14 префабів, 0 Canvas
Menu           25 обʼєктів, 240 префабів, 0 Canvas
```

Canvas немає **ніде**. Немає таймера, лічильника раунду, індикатора фази, кнопки паузи.
`MenuUI` написаний і чекає на кнопки, яких теж нема.

## 3. Звук: 16 клипів є, і майже все підключено

`Audio/Placeholder` має 16 wav. `PlayerEffects` має гачки на всі події бою й руху — удар,
влучання, блок, парі, смерть, кроки, приземлення, лут. Тобто шар є; питання лише в тому,
які кліпи призначені в сцені.

Один гачок мертвий: `Fire(dodge, ...)` — ухил вимкнено.

## 4. Відчуття удару: що було в docs/20 і чого бракувало

| що задумано | стан |
|---|---|
| hitstop у симуляції, обидва бійці | є, детермінований |
| **hitstop видно** | **не було** — аніматор грав далі крізь заморозку |
| трясіння камери і коли влучив ти | є, масштабується від шкоди |
| слід зброї | є |
| **реакція на повторний удар** | **не було** — серія ударів програвала одну реакцію один раз |

Обидві прогалини закриті цим проходом. Це й була частина відчуття «вата».

## 5. Чого в грі ще немає з задуманого

* **суперника немає** — є `FighterBrain` з галочкою, але матч проти людини не тестований;
* **мережі немає** — симуляція детермінована й готова до роллбеку, транспорту нема;
* **`arena_demo_test` застарів** — 41 червоний, не оновлювався;
* **кліпу смерті немає** у паку взагалі, тому `MatchOutcomeView` кладе тіло поворотом;
* **звукових кліпів на бій** — призначення в сцені не перевірене жодним чеком.

## 6. Порядок, у якому це варто робити

1. **Заряди блоку на екрані.** Найменша робота з найбільшим ефектом на чесність бою.
2. **Канвас у матчі**: таймер, фаза, раунд. Без цього матч не читається.
3. **Кліп смерті** — або знайти, або лишити поворот і вимкнути попередження.
4. **Кнопки меню** на вже написаний `MenuUI`.
5. **Оновити `arena_demo_test`**, бо 41 червоний тест — це 41 невідомість.
6. **Бот у матчі за замовчуванням**, щоб гру можна було грати самому.
